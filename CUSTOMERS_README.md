# Customer Module

Complete customer management for the POS system — covers the `customers`, `customer_ledger`, and `credit_notes` tables from `7_point-of-sale.sql`.

---

## Architecture

```
src/
├── types/customers.types.ts        # Interfaces, enums, request/response types
├── validations/customers.validation.ts  # Zod schemas with cross-field validation
├── utils/customers.utils.ts        # Display helpers, formatting, export, filters
├── services/customers.service.ts   # Supabase CRUD for all customer tables
└── stores/customers.store.ts       # Zustand store with cache & optimistic UI
```

---

## Database Tables

| Table | Purpose |
|---|---|
| `customers` | Core customer master — 35+ fields covering identity, credit, loyalty, address, and financial summary |
| `customer_ledger` | Double-entry credit tracking — every debit/credit with running balance |
| `credit_notes` | Store credit issued on returns — redeemable at POS |
| `v_customer_credit_summary` | DB view — outstanding balance, overdue invoices, oldest due days |

### Auto-Generated Fields

- **customer_code** — Auto-generated by `generate_customer_code()` trigger: `STORECODE-CUST0001`
- **customer_ledger.balance** — Running balance maintained by DB
- **credit_notes.amount_remaining** — Generated column (`amount - amount_used`)

### DB Triggers (handled server-side, no client code needed)

| Trigger | Purpose |
|---|---|
| `generate_customer_code()` | Auto-generates customer code on insert |
| `validate_credit_limit()` | Blocks credit sales over limit |
| `handle_sale_completion()` | Updates customer summary (totals, visits, outstanding) + creates ledger entries |
| `record_payment_in_ledger()` | Creates credit entry in ledger, reduces outstanding |

## Validations (`customers.validation.ts`)

All Zod schemas use the `emptyToUndefined` transform for optional string fields.

### Schemas

| Schema | Purpose |
|---|---|
| `createCustomerSchema` | New customer form — phone required, GSTIN regex, credit cross-validation |
| `updateCustomerSchema` | Edit customer — all optional, blacklist requires reason |
| `recordPaymentSchema` | Payment recording — amount + method required |
| `createLedgerEntrySchema` | Manual ledger entry — debit/credit validation |
| `adjustLoyaltyPointsSchema` | Points adjustment — non-zero, with reason |
| `blacklistCustomerSchema` | Blacklist toggle — reason required when blacklisting |
| `customerFiltersSchema` | Filter form validation |
| `customerPaginationSchema` | Pagination params validation |

### Regex Validations

| Field | Pattern | Example |
|---|---|---|
| GSTIN | `^[0-9]{2}[A-Z]{5}[0-9]{4}[A-Z][1-9A-Z][Z][0-9A-Z]$` | `27AAAPL1234C1Z5` |
| PAN | `^[A-Z]{5}[0-9]{4}[A-Z]$` | `ABCDE1234F` |
| Phone | `^[6-9][0-9]{9}$` | `9876543210` |
| Pincode | `^[1-9][0-9]{5}$` | `400001` |

### Cross-Field Validations

- Credit allowed → credit limit must be > 0
- GSTIN provided → company name required
- Blacklisting → reason required
- Ledger entry → exactly one of debit/credit must be > 0

## Store (`customers.store.ts`)

Zustand store with `devtools` middleware. Named `"customer-store"`.

### State

| Field | Type | Description |
|---|---|---|
| `customers` | `Customer[]` | Current page of customers |
| `currentCustomer` | `Customer \| null` | Selected customer detail |
| `dashboardStats` | `CustomerDashboardStats \| null` | Dashboard data |
| `creditSummaries` | `CustomerCreditSummary[]` | Customers with outstanding |
| `ledgerEntries` | `CustomerLedgerEntry[]` | Current customer's ledger |
| `creditNotes` | `CreditNote[]` | Current customer's credit notes |
| `filters` | `CustomerFilters` | Active filters |
| `pagination` | `CustomerPagination` | Current page/limit/sort |
| `searchResults` | `Customer[]` | POS quick search results |

### Loading States

- `isLoading` — Initial data fetch
- `isRefreshing` — Background refresh (data already exists)
- `isSaving` — Create/update/delete in progress
- `isSearching` — POS search in progress

### Cache Strategy

- **5-minute TTL** (`CACHE_TIMEOUT_MS = 300000`)
- `customerCache: Map<id, {data, fetchedAt}>` — Individual customer detail
- `ledgerCache: Map<customerId, {data, total, fetchedAt}>` — Ledger per customer
- `creditNotesCache: Map<customerId, {data, fetchedAt}>` — Credit notes per customer
- `lastFetch` — Timestamp for list cache

### Optimistic UI

All mutations apply changes to local state **before** the server call:

1. **Create** → Prepend to `customers[]`
2. **Update** → Replace in `customers[]` and `currentCustomer`
3. **Delete** → Remove from `customers[]`
4. **Blacklist** → Toggle flags immediately
5. **Payment** → Reduce `outstanding_balance` immediately
6. **Loyalty** → Adjust points immediately
7. **Bulk ops** → Apply to all selected customers

On server error → **rollback** to previous state.
On server success → **replace** optimistic data with server response.

## Usage Examples

### POS Customer Lookup (first thing cashier does)

```tsx
const { lookupByPhone, quickSearch, searchResults, isSearching } = useCustomerStore();

// Exact phone lookup
const customer = await lookupByPhone(storeId, "9876543210");

// Autocomplete search
await quickSearch(storeId, "Raj");
// searchResults now contains matching customers
```

### Create Customer

```tsx
import { createCustomerSchema } from "@/validations/customers.validation";

const result = createCustomerSchema.safeParse(formData);
if (!result.success) {
    // Handle validation errors from result.error.issues
    return;
}

const customer = await createCustomer(storeId, result.data);
```

### Record Payment

```tsx
const success = await recordPayment(storeId, {
    customer_id: "...",
    amount: 5000,
    payment_method: "UPI",
    payment_reference: "TXN123456",
});
// outstanding_balance reflected immediately (optimistic)
```

### Export

```tsx
import { exportCustomersToCSV, downloadCSV } from "@/utils/customers.utils";

const csv = exportCustomersToCSV(customers);
downloadCSV(csv, `customers-${new Date().toISOString().split("T")[0]}.csv`);
```

## Index Alignment

The service queries are designed to leverage these DB indexes:

| Index | Used By |
|---|---|
| `idx_customers_store_phone` | `getByPhone()`, phone search in `getList()` |
| `idx_customers_store_id` | All queries (RLS + explicit filter) |
| `idx_customers_name` (GIN) | Name search in `getList()`, `quickSearch()` |
| `idx_customers_outstanding` (partial) | `getCustomersWithOutstanding()`, `has_outstanding` filter |
| `idx_customer_ledger_customer` | `getLedger()` |
| `idx_customer_ledger_store` | Store-level ledger queries |
| `idx_credit_notes_customer` | `getCreditNotes()` |
| `idx_credit_notes_active` (partial) | `getActiveCreditNotes()` |
